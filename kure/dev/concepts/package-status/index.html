Package Status

What each part of kure does today, what it leaves to you, and what is not built. The rows describe the code at the revision the page was built from.

Words used on this site

WordMeaning
DevelopmentBuilt from the latest commit on main. The notice at the top of every page of the development site names the source commit.
Published prereleaseA tagged release candidate or beta. There is no stable release yet, so every API can still change.
Current supported behaviorWhat the code at the built revision does. A row below says Supported only for that.
ProposedA design that was written down and not built. Its own file says “proposed, not shipped”, and its Go names do not resolve against pkg/.

A status in the table is one of four:

  • Supported: implemented, documented and tested.
  • Limited: implemented with a gap the row names.
  • Consumer-provided: kure defines the interface, and you write the implementation.
  • Not implemented: nothing in the code does it.

AreaPackageStatusWhat it means
Domain modelpkg/stackSupportedCluster, Node, Bundle, Application. ApplicationConfig is consumer-provided: you implement it, and pkg/stack/stacktest checks the generation contract.
Flux workflowpkg/stack/fluxcdSupportedGenerates the Flux objects and the bootstrap manifests, in gotk and flux-operator modes.
Layoutpkg/stack/layoutSupportedWrites the generated tree with WriteToDisk, WriteToTar and WriteManifest.
Argo CD workflowpkg/stack/argocdLimitedGenerates one Application for each layout directory that renders bundles. Bootstrap is not implemented: GenerateBootstrap returns an error when bootstrap is enabled. The repository URL is a placeholder until you call SetRepoURL.
Helm renderingpkg/stack/helmSupportedA library: RenderChart renders a chart without a cluster, and SplitByHookWeight groups the result by hook phase. No workflow calls them; turning a hook group into a Flux Kustomization is your code.
Kubernetes builderspkg/kubernetes and its operator subpackagesSupportedConstructors, per-kind wrappers and sugar helpers. The kinds table lists every registered kind.
Serializationpkg/io, pkg/manifestSupportedYAML and JSON output, resource printing, CRD and scope classification.
Errors, logging, versionspkg/errors, pkg/logger, pkg/versionsSupportedStructured errors, a logger, and the supported-version metadata.
Group, version, kind registrypkg/gvkSupportedA standalone registry and YAML type detection. No other package in this repository imports it.
Command linenoneNot implementedkure ships no CLI. kurel belongs to go-kure/launcher.
